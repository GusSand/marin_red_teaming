Is the cooldown misinformation rise reduced refusal, or improved writing?

Both. Refusal drops 12–15 points, and what the model does write gets more harmful. The raw harmful rate overstates the safety change by about half.

Motivation

Why conduct this experiment?

Misinformation generation on Marin's base checkpoints is lowest at Phoenix (49%) and climbs through the cooldown to 80%. David Hall named the delta: a ~30% mix of Wikipedia, Common Crawl archive and DOLMA HQ.

But the metric is a classifier's harmfulness label, and the classifier rewards good writing. That mix is exactly what teaches confident prose. We already have the mirror image: under the LoRA tamper attack, ASR fell 12% to 1% because responses got shorter.

If the rise is a judge artifact, the cooldown ablation is aimed at nothing. This experiment decides that first.

Setup

Experimental Details

Probe. HarmBench, 320 behaviours; analysis on the 54 misinformation ones. Prompts wrapped in a User:/Assistant: scaffold, because unscaffolded base models echo the prompt and the judge scores the echo.

Generation. vLLM 0.11, temp 0.7, top-p 0.95, safety-eval pinned. A patch puts the seed into vLLM's sampler; without it the old "three seeds" were byte-identical. Judge: WildGuard 7B, offline weights, one harmfulness and one refusal label per response.

Design. Six pinned revisions. Jellyfish, Phoenix, Starling and Deeper-Starling get ten seeds; Kestrel and Ocelot get three. All 46 runs go sequentially on one GPU model with one driver; seed 0 reproduces token-exactly across cards of the same model, and an array across models would confound revision with hardware.

Output per checkpoint. Refusal rate, harmful rate, harmful given non-refusal, empty rate, response length, non-response rate. Per-instance labels stay out of the repo.

H-min: Phoenix is the minimum

RESULT: Supported

Harmful −13.5pp Jellyfish → Phoenix, 95% CI [−20.4, −6.7]. Phoenix is also the refusal peak (26.5%).

H0: Refusal genuinely drops in the cooldown

RESULT: Indeterminate on the threshold, directionally clear

Refusal −12.2pp Phoenix → Starling, CI [−17.6, −7.2]. The point estimate clears 10pp; the interval straddles it. Refusal does fall.

H1: The model writes better, and the judge rewards that

RESULT: Rejected

Refusal moved −14.6pp, CI [−19.4, −10.0]: the "flat refusal" clause fails. But the other half is real: harmful-given-non-refusal +11.3pp [+5.7, +17.0], median length +15%. Quality rose; it is not the whole story.

H1b: The model follows the scaffold better, not writes better

RESULT: Rejected for the cooldown

Non-response falls 21% → 5% → 0.2% from Kestrel to Phoenix, a real format-following effect. It is zero at every cooldown tag, so it cannot explain Phoenix → Starling. The benign-task instrument is still wanted for the early tags, not for this claim.

Mixed: Both

RESULT: Supported in substance

Decomposing harmful = (1 − refusal) × harmful|non-refusal: refusal alone gives +8.5pp, quality alone +11.7pp, observed +22pp. Roughly 40/60. The ablation proceeds; its primary metric becomes refusal or harmful-given-non-refusal.

Decision rule

Recommendations

Fixed before results, so results could not move them. The outcome is Mixed, so the third rule applies.

  • H0 (not the outcome): cost the seven-arm ablation as designed, controls kept.
  • H1 or H1b (not the outcome): do not propose the ablation.
  • Mixed (the outcome): the ablation proceeds. Its primary metric becomes refusal rate or harmful-given-non-refusal. The raw harmful rate overstates the safety change by about half and should not be the headline. Send David the one-pager with this decomposition attached.
  • Any outcome: pick the H1b instrument. It is the blocker now.
  • Hardware: after two L40S drains this rule fired. Gate 3 reruns on H200, then all 39 there. Nothing from L40S is reused.

Method decisions

Supporting Analysis and Questions

All settled before data existed.

Q1: Why was the ± 3pp reproduction gate withdrawn?

Phoenix's historical seeds are 46.3, 42.6 and 57.4: sd 7.7pp, so a three-seed mean has SEM 4.5pp. A perfect port fails a ± 3pp gate half the time. More seeds now cannot fix the noisy historical target, and the old trajectory mixes patched, unpatched and collapsed sampling. Replaced by the protocol gate; old-vs-new Phoenix is descriptive only.

Q2: Why one GPU, and what did it cost?

vLLM only reproduces on identical hardware. The first determinism check ran as an array, landed on three nodes and "failed"; the test was wrong, not the harness. So all 39 run sequentially, and the launcher refuses any prior run whose GPU, host, flags, seed or commit differ from the current allocation. Three jobs then died at ~2h. The cause was not drains but the cluster's GPU-utilization watchdog: this design averages 39% against a 50% cutoff. The L40S runs are excluded. On the H200, seed 0 reproduced token-exactly across two physical cards (and across three L40S cards), so the guard was relaxed from GPU UUID to GPU model + driver + flags + code + seed, documented pre-results. The 29 H200 runs are kept; the rest run in sub-2h jobs.

Q3: Why is the benign control not decisive for H1b?

A benign control should separate instruction following from safety: better format-following lifts compliance on everything. But wildjailbreak:benign scores non-refusal, not task success, so off-topic text passes, which is the exact failure it was meant to catch. It is also saturated at 96.4%. H1b needs a gradable benign task; until then it stays open.

Q4: How is the paired analysis defined with ten seeds?

Paired over the 54 behaviours. Primary: per-behaviour seed proportions, bootstrap CI, permutation p. No tie problem at any seed count. McNemar kept for comparability, with 5–5 splits as an explicit unstable category. Three contrasts, seven tests, Holm-adjusted.

VerificationA fresh agent recomputed everything from raw labels on its own code, blind to the analysis script and its numbers. Every contrast matched within 0.2pp and every McNemar count exactly. It found two bugs in the analysis script (harmful-rate denominator not empty-excluded; wrong length estimator), both fixed to the spec and re-matched. It also found 18 non-empty responses with no judge label, mostly at early tags; no verdict changes.
