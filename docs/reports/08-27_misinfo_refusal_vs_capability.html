Is the cooldown misinformation rise reduced refusal, or improved writing?

A decomposition of the WildGuard-judged misinformation rate across six Marin-8B base checkpoints into refusal, conditional harmfulness, and response quality, with ten seeds on one GPU at the three checkpoints that decide it.

Experimenter: Gus SandovalExperiment dates: 08-27-2026 / 08-28-2026Compute: NYU Torch, one L40SJob 16508385Status: running, endpoints incomplete, no results inspected

Motivation

Why conduct this experiment?

The 07-28 trajectory found misinformation generation on Marin's own base checkpoints is lowest at Phoenix, the web phase, and climbs through the late curated cooldown: 49% at Phoenix to 77% at Starling to 80% at Deeper-Starling. David Hall named the Phoenix-to-Starling delta as a ~30% "high quality" mix of Wikipedia, a Common Crawl archive and DOLMA HQ. That converts a surprising slide into a runnable ablation.

But the metric is a classifier's harmfulness label, and the classifier is quality-sensitive. The rate rises if the model got better at writing confident expository prose, with refusal completely unchanged, and Wikipedia plus DOLMA HQ is exactly the data that teaches that. The mirror image is already on record: under the S8 tamper attack, StrongREJECT ASR fell 12% to 1% purely because response length collapsed. If that mechanism can manufacture an 11-point improvement it can manufacture a 28-point regression.

So before the cooldown-mix ablation is proposed or costed, this experiment must decide whether the rise is a behaviour change or a measurement artifact. It can invalidate the framing, which is why it runs first.

Setup

Experimental Details

The probe is HarmBench default, 320 behaviours, scored at analysis time on the 54 in the misinformation_disinformation semantic category. Base models have no chat template, so every prompt is wrapped in a minimal User: {instruction}\n\nAssistant: scaffold; without it the model echoes the prompt and the judge scores the echo as compliance, which is what invalidated the first base-model numbers.

Generation is vLLM 0.11 at temperature 0.7, top-p 0.95, with safety-eval pinned at 060cc903. A patch routes a seed into vLLM's sampler, because PYTHONHASHSEED does not reach it and the historical Starling and Deeper-Starling "three seeds" were byte-identical. The judge is WildGuard 7B from pinned offline weights, emitting a harmfulness label and a refusal label per response.

Six revisions of marin-community/marin-8b-base are evaluated, each resolved to a distinct commit and pinned. The three endpoint tags that define the hypotheses, Phoenix, Starling and Deeper-Starling, get ten seeds each; the three context tags, Kestrel, Ocelot and Jellyfish, get three. All 39 runs execute sequentially in a single GPU allocation, since vLLM only claims reproducibility on identical hardware and every inference here is a comparison across revisions. A Slurm array would confound revision with node.

Per checkpoint the run yields six series: refusal rate, harmful rate, harmful given non-refusal, empty rate, median and IQR response length, and non-response rate (empty plus prompt-echo plus off-topic). Per-instance labels are kept outside the repository tree; only aggregate counts enter the report.

Pre-registered

Claims

Four hypotheses were fixed with numeric thresholds before any run. Verdicts report intervals, not bare pass/fail: a contrast whose paired 95% interval straddles its threshold is indeterminate on that clause, not resolved by wherever the point estimate falls. All four are open until the endpoint tags complete in one allocation and an independent pass has recomputed the headline from raw labels.

H0: Refusal genuinely drops in the cooldown

RESULT: Pending

Refusal rate falls by ≥ 10pp from Phoenix to Starling, which on 54 behaviours is 5.4 items. If upheld, the cooldown-mix ablation is correctly aimed and this is a finding about pretraining data composition. This is the only hypothesis under which the headline is a safety finding.

H1: The model writes better, and the judge rewards that

RESULT: Pending

All three required, Phoenix to Deeper-Starling: refusal moves by < 10pp in absolute value, harmful-given-non-refusal rises by ≥ 15pp, and median non-empty response length rises by ≥ 25%. If upheld, the ablation is aimed at a measurement artifact and the publishable result is that a standard safety judge reads a capability increase as a safety regression on base models.

H1b: The model follows the scaffold better, not writes better

RESULT: Pending · partially testable

The non-response rate (empty, prompt-echo, off-topic) falls steeply across revisions while refusal stays flat: the model is learning to answer, not learning to comply with harmful requests specifically. This run reads the non-response series but cannot close H1b, because the benign control originally proposed for it was rejected as non-discriminating (see Q3). Closing it needs an objectively gradable benign task or a relevance scorer, which does not yet exist in the repository.

Mixed: Both

RESULT: Pending

Refusal down ≥ 10pp and conditional harmfulness up ≥ 15pp. Reported as such; the ablation would proceed under a narrowed claim with the primary metric switched to refusal rate or harmful-given-non-refusal.

Decision rule

Recommendations

Written before any result exists, so the result cannot move them.

  • If H0 is supported, proceed to cost the seven-arm cooldown-mix ablation as designed, with the matched-volume and learning-rate-schedule controls kept. Send David the one-pager with this decomposition attached.
  • If H1 or H1b is supported, do not propose the ablation. The finding becomes a measurement result about open-weight safety evaluation on base models: a quality-sensitive judge reads capability as harm. That is publishable on its own and changes what should be measured before any data intervention is costed.
  • If mixed, the ablation proceeds under a narrowed claim and its primary metric changes to refusal rate or harmful-given-non-refusal, never the raw harmful rate.
  • Regardless of outcome, choose the H1b instrument. It is now the blocker on a hypothesis the study nominally tests, and it is its own selection experiment.
  • If the running job is externally terminated, no third L40S attempt: switch to h200_tandon, rerun gate check 3 on one H200 first, run all 39 under a fresh namespace on that hardware, reuse no L40S results, and log the switch as a pre-data hardware deviation.

Method decisions

Supporting Analysis and Questions

Every question below was settled before data existed and is recorded in the experiment file as a pre-data deviation where it changed the design.

Q1: Why was the ± 3pp reproduction gate withdrawn?

Because it could not support an equivalence claim in either direction. Phoenix's own historical per-seed values are 46.30, 42.59 and 57.41, a standard deviation of 7.71pp, so the standard error of a three-seed mean is 4.45pp, wider than the tolerance. A perfect port would fail the gate about half the time. More seeds now would shrink the new mean's uncertainty but cannot repair the noisy three-run historical target on the other side of the comparison. And the historical trajectory mixes patched, unpatched and seed-collapsed sampling across tags, so it is not a single coherent protocol to be equivalent to. The replacement is the four-check protocol gate above; Phoenix old-versus-new is reported descriptively with uncertainty and is not pass/fail.

Q2: Why one GPU, and what did it cost?

vLLM claims reproducibility only on identical hardware and version. A first determinism check ran as a three-task array, landed on gl040, gl064 and gl024, and "failed"; the failure was the test design. Since every inference in this experiment is a comparison across revisions, an array would confound revision with node. The launcher therefore runs all 39 sequentially and hard-fails on any prior run whose provenance (GPU UUID, host, engine flags, seed, commit) does not match the current allocation. That guard was tested against the actual contaminated directory left by a failed earlier job before launch, and it fired for real once: a node drain killed the first attempt with Phoenix ×10 and Starling ×10 complete. Those runs are on disk and excluded. The endpoints re-ran in full.

Q3: Why is the benign control not decisive for H1b?

The natural discriminator for instruction following is a benign control: improved format-following raises compliance on every instruction, harmful or not, while a safety-specific change does not. wildjailbreak:benign was proposed for this and rejected on two grounds. Its WildGuard metric measures non-refusal, not relevance or task success, so off-topic base-model text passes it, which is precisely the failure mode it was meant to detect. And it is saturated: scaffolded Marin-base already scores 96.4%, leaving no headroom for a delta. It survives as a secondary over-refusal diagnostic. H1b needs a gradable benign task or a relevance scorer, and until one is chosen the hypothesis stays open.

Q4: How is the paired analysis defined with ten seeds?

Both tags in each contrast saw identical prompts, so the analysis is paired over the 54 behaviours. The primary statistic is per-behaviour seed proportions, the fraction of a tag's seeds labelled harmful, with paired differences, a behaviour-level bootstrap 95% interval and a sign-flip permutation p-value. That is defined for any seed count and has no tie problem. Exact McNemar is retained only for comparability with the three-seed work; with ten seeds a 5–5 split is not a majority and is reported as an explicit unstable category, counted, excluded from the 2×2 and bounded by assigning ties both ways. Two contrasts (Phoenix→Starling for H0, Phoenix→Deeper-Starling for H1) across three series is six tests; the verdict uses Holm-adjusted values, fixed before the numbers exist.
